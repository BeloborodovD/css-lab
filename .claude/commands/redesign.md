Проведи редизайн проекта **$ARGUMENTS** по дизайн-системе css-lab.

Порядок действий (ты — оркестратор, сам код не пишешь):

1. Определи целевой проект: если первый аргумент — не абсолютный путь, ищи
   `D:\_claude_project\<имя>`. Если проект не найден — остановись и спроси.
   Второй аргумент — бренд (по умолчанию `veza`), остальное — охват
   (по умолчанию весь проект).
2. Прочитай регламент целиком: `D:\_claude_project\css-lab\pipeline\README.md`
   и все файлы `pipeline/steps/01..07`. Действуй строго по нему.
3. Ключевые правила регламента:
   - **library-first**: элемент, которого нет в библиотеке, сначала добавляется
     в css-lab (токены → компонент → витрина → e2e → коммит css-lab) и только
     потом применяется в целевом проекте;
   - каждый шаг выполняет закреплённый агент из `css-lab/.claude/agents/`;
   - после каждого генеративного шага — независимая проверка `css-lab-evaluator`,
     принятие только при PASS;
   - контракт параллельных агентов фиксирует DOM id и классы заранее;
   - артефакты шагов — в `<целевой проект>/.claude/redesign/`;
   - git-команды — только с явным `cd` в нужный репозиторий.
4. По завершении (шаг 07 PASS): коммит целевого проекта, push в его ремоуты,
   деплой по регламенту целевого проекта, обновление его `.claude/context.md`.
