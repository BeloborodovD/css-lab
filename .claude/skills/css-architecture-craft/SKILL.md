# CSS Architecture Craft

Свод правил архитектуры стилей этого репозитория. Отвечает на вопросы, которые агенты и
внешние коллеги до сих пор решали угадыванием: какой токен завести и где его объявить,
`--modifier` это или `is-*`, куда положить файл и почему приоритет зависит от порядка
импортов, что вообще разрешено писать числом.

Аудитория — не только агенты этого репозитория, но и коллеги, у которых есть **только этот
репозиторий**. Все правила проверяемы по файлам внутри него; все пути даны от его корня.

## Когда читается — обязательно

- **перед первой строкой CSS** в этом репозитории (новый компонент, правка существующего,
  страничный слой, тема);
- при **добавлении или переименовании токена** — §1 задаёт порядок из пяти шагов, пропуск
  любого ломает тёмную тему или бренд;
- на **шаге 03 конвейера редизайна** (`pipeline/steps/03-library-first.md`), где библиотека
  пополняется новым компонентом, и на **шаге 04** — при поставке стилей в чужой проект (§4.3);
- при **ревью чужого CSS**: §7 — готовый чек-лист приёмки.

## Как включить naming-lint

Скрипт лежит в каталоге скилла и **по умолчанию не подключён** — включается сознательно,
одной правкой `.claude/settings.json`: в существующий блок `PostToolUse` с матчером
`Write|Edit|MultiEdit` добавляется вторая команда рядом с `motion-lint.py`.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/motion-lint.py\" 2>/dev/null || python \"$CLAUDE_PROJECT_DIR/.claude/hooks/motion-lint.py\""
          },
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/skills/css-architecture-craft/naming-lint.py\" 2>/dev/null || python \"$CLAUDE_PROJECT_DIR/.claude/skills/css-architecture-craft/naming-lint.py\""
          }
        ]
      }
    ]
  }
}
```

Перед включением — прогнать самопроверку:

```bash
python .claude/skills/css-architecture-craft/naming-lint.py --selftest
```

Что делает скрипт: **блокирует** цветовой литерал и px-литерал со шкалы в
`styles/components/**` и `styles/pages/**`, а также переключение `--модификатора` из JS;
**предупреждает** о состоянии `is-*` без сеттера, о кегле вне шкалы и об объявлении токена
литералом внутри компонента. Он консервативен и молчит на всём неоднозначном — чтение
[RULES.md](RULES.md) он не заменяет.
