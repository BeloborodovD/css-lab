# css-lab — дизайн-система и библиотека стилей

css-lab — это готовая библиотека стилей на чистом CSS: слой дизайн-токенов, около
шестидесяти компонентов интерфейса, каркас страницы, печатные формы, светлая и тёмная
темы и три сменные темы брендов. Ни сборщика, ни фреймворка, ни зависимостей: всё, что
нужно потребителю, — это несколько CSS-файлов, шрифты и логотипы.

Библиотека рассчитана на плотные прикладные интерфейсы: каталоги оборудования, карточки
изделий, длинные анкеты и опросные листы, панели администратора, журналы событий,
корпоративный поиск, печатные спецификации. Компоненты сделаны сдержанными намеренно —
тонкие границы вместо тяжёлых теней, ограниченная палитра, короткая анимация.

Вместе с библиотекой поставляется сайт-витрина: живые образцы всех компонентов,
страницы-примеры и переключатели бренда и темы, на которых видно, как ведёт себя каждый
компонент в шести сочетаниях «бренд × тема».

---

## С чего начать

```bash
npm install          # только dev-зависимости: локальный сервер и Playwright
npm run dev          # http://localhost:5173 — витрина с автоперезагрузкой
npm run serve        # то же самое без автоперезагрузки
```

Откройте `http://localhost:5173/components.html` — это витрина: слева оглавление
компонентов, сверху переключатели бренда и темы. Страница `index.html` — хаб со ссылками
на страницы-примеры (каталог, карточка изделия, дашборд, форма, вход, печатные формы,
справочник цветов RAL).

Если удобнее контейнер, в репозитории лежат `Dockerfile` (nginx, порт 8080, non-root) и
`Makefile` с целями `make up` (режим разработки) и `make prod` (сборка боевого образа).

## Что где лежит

| Путь | Что это |
| --- | --- |
| `styles/core.css` | Бандл библиотеки: порядок слоёв каскада и `@import` всех файлов |
| `styles/base/` | Токены движения и оформления, сброс, шрифты, утилиты, адаптивные помощники, пользовательские предпочтения |
| `styles/layout/` | Каркас страницы: шапка, подвал, оболочка контента, печатный лист A4 |
| `styles/components/` | Компоненты, один блок — один файл |
| `styles/themes/` | Тёмная тема и три темы брендов |
| `styles/pages/` | Стили страниц-примеров; в бандл не входят |
| `assets/fonts/`, `assets/logos/` | Шрифты (вместе с файлами лицензий) и логотипы |
| `docs/components.yaml` | **Реестр паспортов компонентов** — источник истины о содержимом библиотеки |
| `components.html` | Витрина с живыми образцами |
| `CHANGELOG.md` | Что менялось, на языке потребителя; ломающие изменения помечены **BREAKING** |
| `.claude/skills/css-architecture-craft/RULES.md` | Свод правил оформления: токены, именование, каскад, допустимые литералы |
| `.claude/skills/ui-motion-craft/RULES.md` | Свод правил движения: кривые, длительности, поведение входа и выхода |

**Паспорт компонента** (`docs/components.yaml`) отвечает на вопросы, которых нет в коде:
для чего компонент нужен, когда его брать не стоит, чем он отличается от соседнего,
из каких элементов и состояний состоит, что обязан делать ваш JavaScript, какие токены
компонент читает и где на витрине посмотреть живой образец. Начинать выбор компонента
правильнее с реестра, а не с чтения CSS.

## Подключение к своему проекту

Библиотека подключается копированием файлов в ваш репозиторий (vendoring), а не ссылкой
на чужой сервер. Так вы контролируете момент обновления и не зависите от доступности
источника.

### 1. Скопируйте обязательный слой

Сохраняя имена файлов и структуру каталогов:

```
styles/base/motion.css                → токены движения
styles/base/variables.css             → токены оформления (цвет, шрифт, отступы, тени)
styles/base/fonts.css                 → @font-face фирменных шрифтов
styles/base/reset.css                 → сброс и базовая типографика
styles/base/utilities.css             → утилиты раскладки (по желанию)
styles/base/responsive.css            → адаптивные помощники (по желанию)
styles/base/contrast-preferences.css  → системные предпочтения контраста и прозрачности
```

### 2. Скопируйте тему

`styles/themes/dark.css` — обязательно, иначе тёмная тема будет нерабочей, — и ровно тот
файл бренда, который вам нужен: `veza.css`, `uralelectro.css` или `hemah.css`.

### 3. Скопируйте только те компоненты, которые используете

Компонент может зависеть от другого компонента по композиции — зависимости перечислены в
шапке каждого файла и в паспорте. Например, сводка ошибок формы
(`form-error-summary.css`) рисуется поверх плашки сообщения (`alerts.css`) и без неё
выглядит незаконченной.

### 4. Перенесите ассеты

Шрифты из `assets/fonts/` вместе с файлами лицензий и логотипы из `assets/logos/`
(включая варианты `-mono-light` для тёмного фона). Пути в токенах абсолютные — вида
`url("/assets/logos/veza.svg")`. Либо повторите структуру каталогов у себя, либо
переопределите токены `--brand-logo*` своими значениями.

### 5. Подключите файлы в правильном порядке

Порядок подключения важен только для файлов внутри одного слоя каскада (см. следующий
раздел). Безопасный порядок, повторяющий наш бандл:

```html
<link rel="stylesheet" href="/styles/base/motion.css">
<link rel="stylesheet" href="/styles/base/variables.css">
<link rel="stylesheet" href="/styles/base/fonts.css">
<link rel="stylesheet" href="/styles/base/reset.css">
<!-- утилиты, адаптивные помощники -->
<!-- каркас, затем компоненты -->
<link rel="stylesheet" href="/styles/themes/dark.css">
<link rel="stylesheet" href="/styles/themes/veza.css">
<link rel="stylesheet" href="/styles/base/contrast-preferences.css">
```

Проще всего скопировать `styles/core.css` целиком, удалить из него `@import` неиспользуемых
компонентов и подключать одним файлом. Первая строка `core.css` объявляет порядок слоёв —
её нужно сохранить обязательно.

### 6. Разметка-минимум на вашей стороне

```html
<body data-brand="veza">
```

- `data-brand` на `<body>` выбирает бренд: `veza`, `uralelectro` или `hemah`.
- Класс `dark` на том же элементе включает тёмную тему; без класса библиотека уважает
  системную настройку `prefers-color-scheme`.
- Если тема и бренд запоминаются между визитами, ставьте их до первой отрисовки —
  небольшим встроенным скриптом в `<head>`. Готовый образец такого сниппета есть в
  любой странице этого репозитория.

### 7. Зафиксируйте источник

Рядом с вендоренными файлами заведите короткий файл вида `VENDORED-FROM-CSS-LAB.md`:
перечень скопированных файлов, дата, **точный коммит** библиотеки и список ваших локальных
отклонений, если они есть. Без записи коммита следующее обновление превращается в ручную
сверку глазами.

### 8. Не правьте вендоренные файлы

Нужна другая величина — переопределите токен у себя, отдельным файлом, подключённым после
библиотеки:

```css
/* your-overrides.css — подключается последним */
[data-brand="veza"] {
  --color-accent: #1f6f2c;
}
```

Правка внутри копии теряется при следующем обновлении и не возвращается в библиотеку.

## Каскад: слои вместо порядка подключения

Приоритет правил в библиотеке выражен явно, слоями каскада CSS (`@layer`). Порядок
объявлен одной строкой в начале `styles/core.css`:

```css
@layer tokens, base, legacy, layout, components, themes, pages, overrides;
```

Читается слева направо: слой, объявленный правее, побеждает при равной специфичности
селекторов.

| Слой | Что в нём | Зачем именно здесь |
| --- | --- | --- |
| `tokens` | `base/motion.css`, `base/variables.css` | Значения, которые видят все остальные слои |
| `base` | сброс, утилиты, адаптивные помощники | Правила на тегах и общие классы, которые обязан перекрывать любой компонент |
| `legacy` | `base/animations.css` | Витринный набор старых анимаций; в бандл не входит и библиотеку не перебивает |
| `layout` | шапка, подвал, оболочка, печатный лист | Каркас страницы |
| `components` | `styles/components/*.css` | Сама библиотека |
| `themes` | тёмная тема и бренды | Перекрывают токены поверх компонентов |
| `pages` | `styles/pages/*.css` | Страничные слои: раскладка конкретной страницы сильнее компонентов |
| `overrides` | `base/contrast-preferences.css` | Системные предпочтения пользователя сильнее всего остального |

Что из этого следует для вас:

- **Слой указан внутри каждого файла** (`@layer components { … }`), а не в подключении.
  Файл везёт свою принадлежность с собой, поэтому вендоринг отдельных файлов не ломает
  приоритеты, а форма `@import url(...) layer(name)` нам не нужна — её, к слову, портят
  некоторые сборщики.
- **Оборачивать наши файлы повторно не нужно.** Достаточно один раз объявить порядок слоёв
  (скопируйте строку `@layer …` из `core.css` и разместите её раньше библиотечных стилей).
- **Ваши собственные стили не в слое сильнее любого слоя библиотеки.** Это самый простой
  способ что-то переопределить: пишите свой CSS как обычно, без `@layer`, и он победит.
  Если хотите более тонкую настройку, добавьте собственный слой в конец списка.
- **`!important` работает наоборот.** Для важных объявлений порядок слоёв инвертируется:
  побеждает более ранний слой. В библиотеке `!important` применён считанное число раз
  (переключатели печати и сброс движения), и мы просим не соревноваться с ней важностью.
- **Совместимость.** Слои каскада поддерживаются в Chrome и Edge с 99-й версии, Firefox
  с 97-й, Safari с 15.4. Более старым браузерам библиотека не адресована.

## Темы, бренды и доступность

- Тема бренда переопределяет токены: акцент, дисплейный шрифт, логотип, цвет фирменной
  плашки. **Компоненты о брендах не знают** — селектора `[data-brand="…"]` внутри файла
  компонента быть не должно, ни у нас, ни у вас.
- Свой бренд заводится копией существующей темы: возьмите `styles/themes/veza.css` за
  образец, поменяйте значения токенов и селектор `[data-brand="ваш-бренд"]`, не забыв
  блоки тёмной темы в конце файла.
- Цветовые пары проверены по WCAG: у большинства текстовых сочетаний контраст не ниже
  4.5:1, у основного текста — выше 7:1; посчитанные значения записаны комментариями рядом
  с токенами.
- Учтены системные предпочтения: `prefers-color-scheme`, `prefers-contrast: more`,
  `forced-colors`, `prefers-reduced-transparency` и `prefers-reduced-motion`. Пониженное
  движение делает анимацию мягче, а не выключает её полностью: интерфейс обязан оставаться
  понятным.
- Минимальные размеры целей нажатия соблюдены: мелкие управляющие элементы не меньше
  24 × 24 px, основные — 44 × 44 px.

## Если вы работаете на React или другом фреймворке

- Подключайте наш CSS **глобально**, одним импортом в корне приложения. Не превращайте его
  в CSS Modules: хеширование имён ломает публичный контракт классов (`.btn`, `.is-open`),
  на который опираются разметка и тесты, и рвёт темизацию через `data-brand` и `dark`,
  работающую от предков.
- Поведение (фокус-ловушки, порталы, семантика списков) берите из зрелых библиотек
  компонентов, а стили — у нас: выдавайте узлам библиотеки наши классы либо переопределяйте
  их переменные нашими токенами.
- Состояния, которые ваша библиотека отдаёт атрибутами (`data-state="open"`,
  `aria-expanded`), стилизуйте напрямую по атрибуту — заводить зеркальные классы не нужно.

## Соглашения кода — коротко

Если вы дополняете библиотеку или пишете стили рядом с ней, полезно знать три правила;
полный свод — в `.claude/skills/css-architecture-craft/RULES.md`.

1. **Один компонент — один файл**, имя файла совпадает с именем блока, все селекторы файла
   начинаются с этого имени. Элементы пишутся через `__`, ровно одним уровнем.
2. **`--модификатор` — это вариант**, который автор разметки выбирает один раз и больше не
   меняет. **`is-*` — это состояние**, которое переключает скрипт во время работы страницы.
   Скрипт никогда не трогает класс с `--`.
3. **Никаких литералов.** Цвет, кегль, отступ, скругление, тень, слой, длительность и
   кривая берутся из токенов. Закрытый список исключений (миллиметры печати, размеры
   системных контролов, значения брейкпоинтов) перечислен в своде правил.

Проверка перед отправкой изменений: `npm run test:e2e` — сквозной прогон всех страниц
в Playwright.

## Лицензии и шрифты

Шрифты лежат в `assets/fonts/` вместе с текстами лицензий (SIL OFL, Apache 2.0). Копируя
шрифты в свой проект, переносите файлы лицензий рядом — этого требуют их условия.
Фирменные логотипы и цвета брендов принадлежат правообладателям и используются в рамках
их руководств по фирменному стилю.
