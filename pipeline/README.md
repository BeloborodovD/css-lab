# Пайплайн «Редизайн проекта по библиотеке css-lab»

Регламент для оркестратора (главный агент Claude Code). Запускается фразой вида:

> «отредизайнь проект X по css-lab» / «приведи проект X к дизайн-системе»

Пример готового запроса (скопируйте и замените путь):

```text
Используя проект css-lab, необходимо провести редизайн проекта
D:\_claude_project\phoenix-dashboard по пайплайну css-lab/pipeline.
Бренд — VEZA, охват — весь проект. Новые элементы — сначала в библиотеку.
```

## Слэш-команда /redesign

Короткий способ запуска — команда `/redesign` (`.claude/commands/redesign.md`;
копия лежит в `.claude/commands/` корня воркспейса, чтобы работать из любой сессии):

```text
/redesign <имя-или-путь-проекта> [бренд] [охват]
```

| Аргумент | Значение | По умолчанию |
| --- | --- | --- |
| проект | имя в `D:\_claude_project\<имя>` или абсолютный путь | обязателен |
| бренд | `veza` \| `uralelectro` \| `hemah` | `veza` |
| охват | свободный текст: какие страницы/разделы редизайнить | весь проект |

Примеры:

```text
/redesign motor-selector
/redesign phoenix-dashboard uralelectro только страницы каталога
/redesign D:\_claude_project\cert-data hemah
```

Команда разворачивает этот регламент целиком: чтение шагов, library-first,
закреплённые агенты, гейты `css-lab-evaluator`, артефакты в
`<проект>/.claude/redesign/`, в конце — коммит и деплой целевого проекта.

Цель: привести целевой проект к дизайн-системе css-lab — токены, компоненты, движение,
эргономика — силами специализированных агентов из `css-lab/.claude/agents/`.

## Главный закон — library-first

**Новый элемент, найденный в целевом проекте и отсутствующий в библиотеке, сначала
добавляется в css-lab** (по общему дизайну: токены, BEM, motion-контракт, витрина,
e2e-тест), **и только потом применяется в целевом проекте** уже как компонент
библиотеки. Прямой перенос «самописного» элемента в редизайн — дефект пайплайна.

Порядок при находке нового элемента: шаг 03 (библиотека) → коммит css-lab → шаг 04
(применение). Целевой проект никогда не получает стили, которых нет в библиотеке.

## Карта шагов и закреплённые агенты

| Шаг | Файл | Агент (css-lab/.claude/agents) | Выход |
| --- | --- | --- | --- |
| 01 Аудит | [steps/01-audit.md](steps/01-audit.md) | `dev-ux` (+ `dev-landing-page` для лендингов) | audit.yaml: экраны, элементы, проблемы эргономики |
| 02 Маппинг | [steps/02-mapping.md](steps/02-mapping.md) | `dev-css` | mapping.yaml: элемент → компонент css-lab / gap / **new** |
| 03 Библиотека | [steps/03-library-first.md](steps/03-library-first.md) | `dev-brand-identity` → `dev-css` → `dev-frontend` → `dev-web-animation` | новые компоненты в css-lab + витрина + тест + коммит |
| 04 Применение | [steps/04-apply.md](steps/04-apply.md) | `dev-css` + `dev-frontend` (параллельно, файлы не пересекаются) | целевой проект на токенах и компонентах css-lab |
| 05 Движение | [steps/05-motion.md](steps/05-motion.md) | `dev-web-animation` | анимации по RULES.md ui-motion-craft |
| 06 Доступность | [steps/06-a11y.md](steps/06-a11y.md) | `dev-accessibility` | WCAG 2.2 AA: фокус, клавиатура, контраст |
| 07 Верификация | [steps/07-verify.md](steps/07-verify.md) | `css-lab-evaluator` (скептик, специализирован под css-lab) | PASS/REJECT; при PASS — git → push → deploy |

Шаги 01–02 читающие, идут параллельно двумя агентами. Шаг 03 выполняется только при
непустом списке `new` из маппинга. Шаги 04–06 последовательны (общие файлы). После
каждого генеративного шага — проверка `css-lab-evaluator` (assume broken), принятие
только при PASS.

## Правила оркестрации

- Оркестратор сам код не пишет: разбивает работу, фиксирует контракты, сводит
  результаты, коммитит и деплоит. Вся работа — у агентов.
- Каждому агенту в промпт: путь до целевого проекта, путь до css-lab, его шаг-файл
  из `pipeline/steps/`, артефакты предыдущих шагов.
- Контракт параллельных агентов обязан фиксировать все DOM id и классы заранее —
  иначе нэйминг разойдётся.
- **Рабочий набор путей.** В начале прогона оркестратор объявляет две области:
  репозиторий css-lab и целевой проект. Запись в любой другой проект воркспейса
  запрещена — доноры и соседние проекты читаются, но не правятся.
- Артефакты шагов (audit.yaml, mapping.yaml, отчёты) — в
  `<целевой проект>/.claude/redesign/`, не в css-lab.
- Источник истины о содержимом библиотеки — реестр паспортов
  `docs/components.yaml`; закон оформления стилей — скилл
  `.claude/skills/css-architecture-craft/RULES.md`, движения —
  `.claude/skills/ui-motion-craft/RULES.md`.
- Агенты `dev-*` не имеют инструмента Skill — скиллы css-lab они читают через Read
  по путям из своих промптов (`css-lab/.claude/skills/...`).

## Поставка библиотеки в целевой проект

Библиотека — чистый CSS, подключается копированием (vendor), а не ссылкой:

1. Обязательный слой: `styles/base/motion.css` (первым в каскаде!),
   `styles/base/variables.css`, `styles/base/fonts.css` + нужные шрифты из
   `assets/fonts/` и логотипы из `assets/logos/`.
2. Тема бренда целевого проекта: `styles/themes/<brand>.css`, атрибут
   `data-brand` на `<body>`.
3. Только используемые компоненты из `styles/components/` — не весь core.css.
4. В целевом проекте фиксируется файл `VENDORED-FROM-CSS-LAB.md` со списком
   скопированных файлов и коммитом css-lab — для будущей синхронизации.
5. React-проекты: стили берутся отсюда темой, поведение — библиотеки по вердикту
   pick-ui-library (Sonner — тосты, base-ui — диалоги/поповеры, react-day-picker —
   календарь).
