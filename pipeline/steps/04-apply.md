# Шаг 04 — Применение в целевом проекте

**Агенты:** `dev-css` (стили/поставка библиотеки) + `dev-frontend` (разметка,
классы, состояние) — параллельно по непересекающимся файлам, контракт DOM id и
классов фиксирует оркестратор до запуска.

**Вход:** mapping.yaml (все вердикты теперь `exists`), css-lab на актуальном
коммите.
**Выход:** целевой проект на токенах и компонентах css-lab.

## Задача dev-css

1. Vendor-поставка по разделу «Поставка» из `pipeline/README.md`: base-слой
   (motion.css первым!), тема бренда, только используемые компоненты, шрифты и
   логотипы. Создать `VENDORED-FROM-CSS-LAB.md` (список файлов + коммит css-lab).
2. Удалить/заместить старые стили заменённых элементов; временные мосты старых
   классов на новые не оставлять — правится разметка (dev-frontend).
3. `data-brand` на `<body>`, поддержка `.dark`, анти-FOUC сниппет.

## Задача dev-frontend

1. Перевести разметку заменяемых элементов на классы компонентов css-lab из
   mapping.yaml (точные имена — из контракта).
2. Поведение (открытие панелей, фокус-возврат, inert, scroll-lock) — по образцам
   `css-lab/main.js`; в React-проектах поведение — из библиотек по вердикту
   pick-ui-library, стили — темой css-lab.
3. Ошибок консоли быть не должно; существующие тесты целевого проекта не ломать.

## Батчинг для больших проектов

Проект больше ~5 страниц не редизайнится одним проходом: агент утонет в контексте,
а время растёт линейно по страницам. Оркестратор режет работу:

1. **Единица батча — страница или маршрут**: естественная граница непересекающихся
   файлов. Общий слой (vendor-поставка, глобальный CSS проекта, шапка/подвал)
   правится один раз в нулевом батче, до параллельных.
2. **Контракт имён фиксируется на весь проект**, а не на батч, — иначе нейминг
   разойдётся между потоками.
3. Батчи идут **параллельно**, 3–5 одновременно.
4. Гейт `css-lab-evaluator` — **на батч**, а не на каждый файл. Пятикратный
   стабилизационный прогон тестов — один раз, на финальном гейте шага 07.
5. **Коммит после каждого проверенного батча**: длинный прогон переживает обрыв,
   прогресс виден, откат точечный.

Шаги 05–06 режутся по тем же границам.

## Гейт

Все `exists`-элементы заменены (grep старых классов пуст либо каждое оставшееся
вхождение обосновано в отчёте), проект собирается/открывается без ошибок консоли.
