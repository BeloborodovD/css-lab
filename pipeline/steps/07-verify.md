# Шаг 07 — Верификация и внедрение

**Агент:** `css-lab-evaluator` (скептик; локальный агент в
`css-lab/.claude/agents/`, специализированный под css-lab — знает матрицу
бренд/тема, контрастные гейты, token-грепы и деплойный путь проекта; работает
действием: запускает тесты и ходит по UI через Playwright). На машинах без
css-lab fallback — глобальный `loop-evaluator` из `~/.claude/agents/`.
Внедрение — оркестратор.

**Вход:** целевой проект после шагов 04–06, mapping.yaml, отчёты шагов.
**Выход:** вердикт PASS/REJECT; при PASS — редизайн в проде.

## Стоп-условие PASS (все пункты)

1. Тесты целевого проекта зелёные (свои + добавленные при редизайне).
2. Playwright-проход по страницам из audit.yaml: без ошибок консоли, панели
   открываются/закрываются, фокус живой, тёмная тема и бренд переключаются.
3. Ни одного стиля мимо библиотеки: grep целевого проекта на локальные копии
   цветов/кривых, задублированные компоненты — чисто.
4. `VENDORED-FROM-CSS-LAB.md` актуален (файлы и коммит css-lab совпадают).
5. Скриншоты до/после ключевых страниц — в `<target>/.claude/redesign/shots/`.

## При REJECT

Точечный возврат на шаг-виновник (04/05/06) тому же агенту с цитатой отказа;
после исправления — повторная верификация. Не чинить руками оркестратора.

## Внедрение (боевой режим)

При PASS оркестратор в ту же сессию: коммит целевого проекта → push во все его
ремоуты → сборка/деплой по регламенту целевого проекта → smoke на проде
(браузерный UA). Обновить `<target>/.claude/context.md` и артефакты redesign/.

## Итоговый CHANGELOG

Каждый прогон завершается записью в `css-lab/CHANGELOG.md` (корень репозитория) —
это лицо библиотеки для коллег, у которых нет ни доступа к нашим проектам, ни
желания читать git log.

Правила записи:

- **Резюме, а не протокол.** Одна-две строки на смысловое изменение: что теперь
  можно и что поменялось для потребителя. Ни номеров коммитов, ни списков файлов,
  ни цифр контрастов и длительностей — за деталями есть git и паспорта.
- Группировать по смыслу: «Добавлено», «Изменено», «Исправлено», «Убрано».
- Ломающие изменения (переименование классов, удаление компонента, смена
  контракта) — отдельной пометкой, с указанием, что делать потребителю.
- Пишется на языке пользователя библиотеки: «выпадающие списки умеют группы и
  колонки», а не «picklist__group + panel--columns».
- Правки, которые потребителя не касаются (внутренний регламент, тесты,
  документация процесса), в CHANGELOG не попадают.

Если в прогоне менялась библиотека (шаг 03), витрину нужно выкатить отдельно —
**автодеплоя нет**: HR клонирован с ветки `main` GitLab, поэтому пуша в
`feature/*` недостаточно.

```bash
cd /d/_claude_project/css-lab && git -c credential.helper= push gitlab feature/lightweight-redesign:main
ssh ServerHr "cd ~/docker/css-lab && git pull && docker compose -f docker-compose.hr.yml up -d --build"
```

Проверять прод только браузерным User-Agent — ModSecurity режет UA curl'а.
